# 第二部分：第二轮排查发现（20:20–20:35）

## 🔴 R2-01 [P0] 构建必挂：tsc 类型错误
```
npx tsc -p tsconfig.app.json --noEmit → exit 1
src/App.test.tsx 内 TS2769 ×12：'exact' does not exist in type 'ByRoleOptions'
```
- 错误数在两次运行间 9 → 12（测试文件还在继续加 `exact: true`，方向反了）。
- vitest 不做类型检查 ⇒ 绿测 ≠ 可构建；`npm run build` 前置 `tsc -b` 必失败。
- 根因线索：package.json 全部依赖用 `"latest"` 浮动版本；当前安装版本的 @testing-library/dom 类型不含 ByRoleOptions.exact。
- 建议：去掉 exact 用法（中文名按钮天然唯一）或固定 @testing-library 版本。

## 🟠 R2-02 [P1] 单元测试套件不稳定（flaky）
同一工作区六次运行失败数：**9 → 2 → 1 → (并行修复) → 1 → 0 → 0**。
- 部分波动是并行编辑叠加所致（跑测试时文件在变），不能全归咎代码；
- 但"单独跑 App.test.tsx 全绿、全套跑偶发挂 1 个"的模式稳定复现 2 次，指向跨文件干扰脆弱性；
- 结构性诱因：`App.tsx` 模块级共享单一 `appStore`（createGameStore 于模块顶层实例化）+ rAF 真实计时器驱动模拟循环 + 2400ms effect 定时器，测试间状态残留敏感。
- 建议：模拟时钟注入 fake timers；每测试显式重置 store。

## 🟠 R2-03 [P1] E2E 即将断链（高风险预测，基于 20:27 版 smoke.spec.ts diff）
```ts
await page.getByRole('tab', { name: '旅行', exact: true }).click();
await page.getByRole('button', { name: '加入购物袋：现磨咖啡' }).click();   // 商品！
await page.getByRole('button', { name: '加入购物袋：实用手机' }).click();
```
而当前 App.tsx 中 `renderItemCard` 仅在 `tab === 'goods'` 分支渲染（唯一调用点）。旅行 Tab 下只有活动卡，没有商品卡 → 两条加购断言必然超时。若并行会话后续让分类 Tab 渲染对应分类商品则此条作废。

## 🟠 R2-04 [P1] 中文可读性：小字号泛滥（2026-08-29 20:29 实测）
生活页 `.main-content` 内 **56 个元素 font-size < 11px**，抽样：
- `console-kicker` 10px："主循环 · 现在"、"当前活动"、"时间速度"
- `progress-caption` 10px："50% · 今日活动进度"
- `text-button.month-run` 10px —— 可交互按钮文字！("运行 1 个月"/"运行 3 个月")
- 计划摘要 `<dt>/<dd>` 10px："本周工资"、"¥480"

规范红线："不要为了像素风牺牲中文可读性"。连交互控件都在 10px，需整体提一档（建议正文≥13px、辅助信息≥11px、按钮禁用<12px）。

## 🟡 R2-05 [P2] ShopView Tab 不跟随跳转
`ShopView` 只用 `useState(initialTab)` 且无 useEffect 同步 `initialTab`：
- 在商店页内点击"先准备再安排"类链接时，App 层 `shopTab` 被置 `'goods'`，但已挂载视图内 Tab 不变；
- 下次冷进商店会被上次遗留状态决定初始 Tab（除非从城市跳转，那种走重挂载路径正常）。

## 🟡 R2-06 [P2] 顶栏设置入口非语义控件
`<span className="settings-button" aria-label="设置">` 不是 `<button>`：不可聚焦、Enter 无效、角色缺失，违反项目自身约定（AGENTS.md "keep controls semantic and accessible"）。

## 🟡 R2-07 [P3] 其他观察

## 仍然开放的问题（截至 20:45 源码状态）

### 🟠 R3-01 [P1] 每次 dispatch 都同步写存档（含热路径）
`gameStore.ts` dispatch 内无条件 `saveGameState(result.state)`（JSON.stringify 整个 GameState + localStorage.setItem 同步执行）。而 `App.tsx` 的 rAF 循环在模拟运行时以最高约 120 次/秒调用 `{type:'advance_simulation'}` —— 即运行中每秒上百次全量序列化+同步写。存档随游戏时长增长（lifeHistory、worldHistory、月度账本累积），主线程成本线性上涨。
建议方向：写时去抖（如暂停/决策门/每 N 秒合并落盘），或仅对持久性动作即时写。

### 🟠 R3-02 [P1→复核] 页面长度失控转移到了财富页
全 7 视图实测高度（视口 1086px）：财富 **6007px**(≈5.5 屏) > 社交 3304 > 生活 2603 > 职业 2677 ≈ 我的 2096 > 城市 1615 > 商店 1211✅。
财富页细分：`asset-columns` 单块 **3215px**（投资+企业+资产全部堆叠），其后还有 1536px 的"获取路径"面板。信息架构与当初商店页同病：未按参考图的"单屏画布 + 分组节奏"收敛。
（同类观察：职业页 tiny<11px 元素达 **141 个**为全站之最，商店 87、生活 56。）

### 🟠 R3-03 [P2] 小字号问题是全局系统性的
styles.css 中 font-size ≤12px 的声明共 **230 处**：10px×67、11px×66、12px×58、9px×27、8px×10、**7px×2**。不是局部修正能解决的，需要定排版阶梯（正文≥13 / 辅助≥11 / 徽标可 10）并全局收敛。

### 🟡 R3-04 [P2] 弹窗无焦点管理与 Escape 支持
App.tsx 与 CareerView.tsx 中不存在任何 `.focus()` / keydown / Escape 处理。所有弹窗（事件/Offer/奖励/离职/招聘/重置确认/月结算）打开后焦点仍留在底层页面，Tab 会先穿越背景内容；背景也不锁定滚动。
注：月结算必须显式确认是合理设计，但焦点应初始落入弹窗。

### 🟡 R3-05 [P2] 已隐藏组件成为死标记
`.metric-strip { display:none }`（dark 主题段）使顶栏下"生活水平/能力/声誉/关系"指标条在所有页面均为 0 高度但仍渲染进 DOM。要么删组件，要么让它回归设计。

### 🟡 R3-06 [P3] 轻微横向溢出（3–5px）
实测三处子元素比容器宽且未被 overflow:auto 吸收：
- 职业页 `.forecast-strip`（1396 vs 1401）
- 商店页 `.shop-main`（1088 vs 1091）、`.shop-detail`（1084 vs 1089）
典型 grid min-width 收缩问题，`minmax(0,·)` 或 `min-width:0` 可解。

### 🟡 R3-07 [P3] 损坏存档被静默替换
`loadGameState` 有 try/catch，但 catch 分支直接 `createInitialState` —— 存档损坏时玩家进度无声丢失且无提示。与 AGENTS.md"保护正常浏览器存档"的精神相比，至少应给出一次性警告或把坏档备份到另一 key。

### 🟡 R3-08 [P3] ShopView initialTab 不回灌（同 R2-05，仍在）
`useState(initialTab)` 无 useEffect 同步；商店内再触发 navigateToView('shop') 时 App 层与视图层 Tab 状态分叉。
